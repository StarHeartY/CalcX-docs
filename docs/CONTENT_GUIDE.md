# 内容编写规范

本规范适用于 `pages/` 下发布给 CalculatorX 用户的中文帮助内容。目标是让页面准确、可检索、易维护，并能由维护者或 AI 在不了解历史对话的情况下继续完善。

## 内容事实

- 只描述已从 CalculatorX 当前实现、配置、发布说明或维护者信息核实的功能；
- 不根据页面标题、占位内容或旧版本文案推断功能已经可用；
- 涉及版本、兼容系统、联网行为、隐私、下载地址和操作路径时重新核实；
- 无法核实的内容留在任务讨论中，不写入正式用户手册；
- CalculatorX 主项目是产品实现的权威来源，本仓库不复制其内部架构文档。

## 选择 Markdown 或 MDX

默认使用 `.md`。只有以下情况才使用 `.mdx`：

- 需要导入 `Cards`、`ThemeImage`、`HelpLink` 等组件；
- 需要 JSX 布局或受控交互；
- 普通 Markdown 无法清晰表达页面结构。

不要为了简单文字、列表、表格或图片把页面升级为 MDX。MDX 变更的构建风险更高，也需要注意 JSX 语法。

## 页面基础结构

每个页面至少包含标题 Front Matter 和一个一级标题：

```md
---
title: 页面标题
description: 一句话说明页面帮助用户完成什么
---

# 页面标题

用一段简短介绍说明适用场景和读完后的结果。

## 操作步骤

1. 第一步。
2. 第二步。

## 注意事项

- 说明限制、模式差异或容易误解的行为。
```

`description` 在能够准确概括页面时添加，用于搜索引擎和分享元信息。页面标题应与导航名称含义一致，但可以根据阅读语境稍作扩展。

## 标题与语言

- 每页只保留一个 `#` 一级标题；
- 从 `##` 开始组织主要章节，不跳跃标题层级；
- 标题应具体表达任务或能力，避免“其他”“更多”等模糊词；
- 使用简体中文和一致的产品术语；
- 首次出现专业术语时给出中文解释，必要时附英文缩写；
- 将按键上方以橙色标出的功能统一称为“Shift 功能”，只在首次帮助用户定位时说明橙色标签；
- 面向用户描述结果和操作，不记录编写过程、争论或临时决策；
- 避免“极致”“完美”“终极”等无法验证的宣传性措辞。

## 导航

同级页面的顺序和名称由目录中的 `_meta.js` 决定。新增页面时：

1. 创建语义清晰、使用小写英文的文件名；
2. 在同级 `_meta.js` 中添加对应键；
3. 将页面放到符合主题的已有目录，避免只为一个页面建立新分类；
4. 检查上一页、下一页、侧边栏和移动端菜单；
5. 只有存在真实目标页面时才添加首页卡片或正文入口。

分类名称、文件夹名称和路由一旦发布，应尽量保持稳定。调整路由时需要同步修正内部链接和外部入口。

## 链接

- 优先链接到具体页面或具体标题，而不是只有分类名的空入口；
- 使用 Next.js `Link`、Nextra 组件或基于它们的组件时，传入不含 `/docs` 的站内路由，例如 `/faq`；
- 原生图片、图标或 `next/image` 资源路径需要考虑 `/docs` basePath；
- 工程文档使用相对文件链接，保证在 GitHub 和本地都可导航；
- 外部链接使用稳定的官方来源；
- 不把 Cloudflare Preview URL 写成长期入口；
- 修改标题后检查所有指向旧锚点的链接。

## 图片

原始图片放在 `public/images/` 下。页面专属图片按照页面路由分组，使页面源码与图片目录保持对应：

```text
pages/basics/arithmetic.mdx
public/images/docs/basics/arithmetic/<name>.png
public/images/docs/basics/arithmetic/<name>_dark.png
```

根级页面直接使用同名目录，例如 `pages/history.mdx` 对应 `public/images/docs/history/`。没有图片的页面不需要提前创建目录。同一张图片被多个页面复用时只保留一份，放在主要归属页面的目录中；确实不属于某个具体页面的模块公共图片可以放在对应 `<section>` 根目录。

要求：

- 文件名使用小写英文、数字和连字符；
- 明暗主题成对图片使用 `_dark` 后缀；
- `alt` 准确描述图片展示的界面或结果，不能写“图片”“名字”等占位词；
- `ThemeImage` 会使用图片的天然尺寸，无需在页面中手工填写宽高；
- 需要缩小显示时使用样式限制宽度，并保持 `height: 'auto'`；
- 不手动提交构建后的 WebP；源文件保留 PNG/JPG，构建脚本负责产物转换；
- 新截图不得包含账号、密钥、个人通知或其他不应公开的信息。

使用 `ThemeImage` 的示例：

```mdx
import ThemeImage from '../../components/ThemeImage'

<ThemeImage
  src="/images/docs/scientific/overview/overview.png"
  alt="CalculatorX 科学计算主界面"
  style={{ maxWidth: '240px', height: 'auto' }}
/>
```

组件使用原生图片的懒加载能力，并自动尝试加载同目录下的 `_dark` 图片；暗色图片不存在时回退到普通图片。

### 行内按键图标

操作步骤需要用户点击或长按 CalculatorX 的退格键时，使用 `BackspaceKey` 显示应用中的实际图标，不直接复制 SVG 代码：

```mdx
import BackspaceKey from '../../components/BackspaceKey'

点击 <BackspaceKey /> 删除光标前的内容。
```

组件会通过 `aria-label` 保留“退格键”的无障碍含义，并使用 `public/icon/icon_backspace.svg` 作为随明暗主题变色的图标遮罩。功能概述、并列名词、图片 `alt` 和页面标题等普通文字场景仍写作“退格”或“退格键”，不要在连续文字中突兀地插入图标。

## 视频

需要展示光标移动、连续按键或界面手势等动态过程时，优先使用短视频，不使用 GIF 代替。视频文件放在 `public/videos/docs/` 下，并按页面或主题分组：

```text
public/videos/docs/<section>/<name>.mp4
public/videos/docs/<section>/<name>_dark.mp4
```

视频推荐使用无音轨的 H.264 MP4，删除录制前后的等待片段，并保持足以看清操作的画质。页面通过 `ThemeVideo` 引用视频：

```mdx
import ThemeVideo from '../../components/ThemeVideo'

<ThemeVideo
  src="/videos/docs/basics/nested-cursor.mp4"
  ariaLabel="使用方向键在分数的分子和分母之间移动光标"
  style={{ maxWidth: '240px', borderRadius: '12px', marginTop: '16px' }}
/>
```

组件默认静音、循环、行内自动播放并显示控制栏；系统启用“减少动态效果”时会停止自动播放。组件会自动尝试加载同目录下的 `_dark` 视频，深色变体不存在时回退到普通视频。不要在一个页面中连续放置大量自动播放视频。

## 数学公式

项目已启用 LaTeX。短公式使用行内语法：

```md
一元二次方程写作 $ax^2 + bx + c = 0$。
```

独立推导使用块级语法：

```md
$$
x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
$$
```

- 公式前后补充文字解释；
- 不用截图代替可表达的数学公式；
- 示例必须与 CalculatorX 实际输入和输出格式一致；
- 复杂公式在开发环境和构建产物中都要检查。

## 操作步骤和示例

- 一组步骤只解决一个明确任务；
- 使用有序列表表达顺序，使用项目符号表达并列说明；
- 按键名称与应用界面保持一致，必要时使用 `<kbd>`；
- 同时说明前置模式、角度单位、精确/小数设置等会影响结果的条件；
- 输入、输出和预期结果必须能够被复现。

## 占位页面

框架阶段可以保留“敬请期待”页面，但应满足：

- 页面标题和导航分类已经确定；
- 不在首页或正文中把占位页面描述为完整教程；
- 开始撰写时一次性替换占位内容，不在正式页面中留下内部 TODO；
- 没有目标页面时暂缓添加入口链接。

## 提交前检查

- 标题、导航名称和文件名对应；
- 产品功能、版本和操作路径已核实；
- 页面在亮色、暗色和窄屏下可读；
- 图片 alt、尺寸和 `_dark` 变体正确；
- 数学公式正常渲染；
- 内部链接、外部链接和锚点有效；
- 没有把工程过程、私密信息或占位措辞写入正式内容；
- 按[开发指南](DEVELOPMENT.md)完成与风险匹配的验证。
