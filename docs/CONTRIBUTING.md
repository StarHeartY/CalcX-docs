# 贡献指南

CalcX-docs 当前由项目维护者负责，并主要通过 AI 辅助完成调查、编写和验证。本指南定义仓库内部的标准变更流程，也为可能出现的外部建议或补丁提供最小约定。

## 开始之前

根据任务阅读：

- [项目 README](README.md)
- [工程文档索引](docs/README.md)
- [开发指南](docs/DEVELOPMENT.md)
- [内容编写规范](docs/CONTENT_GUIDE.md)
- [AI 协作规则](AGENTS.md)

如果任务涉及 CalculatorX 产品功能，先获得当前应用实现或维护者提供的事实。不要只根据现有占位页面补写教程。

## 贡献类型

### 用户手册内容

包括教程、FAQ、截图、公式、导航和产品说明，主要修改 `pages/` 与 `public/images/`。必须遵循[内容编写规范](docs/CONTENT_GUIDE.md)。

### 工程维护

包括组件、样式、依赖、构建脚本、工程文档和部署说明。开始前应阅读[架构说明](docs/ARCHITECTURE.md)，并执行与风险匹配的构建验证。

## 标准流程

1. 明确任务目标、文件边界和事实来源；
2. 检查工作区已有修改，避免覆盖维护者内容；
3. 较大变更使用短期分支，单一小修改可由维护者决定是否直接处理；
4. 只修改完成任务所需的文件；
5. 根据[开发指南](docs/DEVELOPMENT.md)执行检查；
6. 较大内容或结构变更使用 Cloudflare Preview 审查；
7. 在交付或 PR 描述中说明范围、验证和未完成事项；
8. 由维护者决定合并和生产发布。

## 分支与提交

- 一个分支处理一个明确主题；
- 分支名使用简短的小写英文和连字符或斜杠，例如 `docs/content-guide`；
- 提交信息应描述结果，而不是只写“update”或“fix”；
- 不把无关格式化、依赖升级和内容改写混入同一提交；
- 不提交 `.next/`、`out/`、`out_temp/`、`node_modules/`、日志或本地设计文件。

## Pull Request 或交付说明

至少包含：

- 为什么需要这次修改；
- 修改了哪些文件和页面；
- 产品或配置事实从哪里核实；
- 执行了哪些命令和目视检查；
- 哪些内容没有验证；
- 是否影响 `/docs` 路径、Cloudflare 或客户端离线产物。

不要把临时 Preview URL、私密配置或账号截图长期写入仓库。

## 审查清单

- 修改边界与任务一致；
- 没有覆盖已有未提交工作；
- 页面、导航、链接和标题保持一致；
- 图片、公式和明暗主题表现正确；
- 工程文档与实际配置一致；
- 依赖变更同时更新 `package-lock.json`；
- 需要构建的修改已经成功生成 `out/docs/`；
- 交付说明明确列出验证结果。

## 外部贡献

仓库当前不以建设大型贡献者社区为目标。外部 Issue 或 Pull Request 是否采纳由维护者根据项目方向决定；提交前建议先说明问题和预期范围，避免投入到暂不计划维护的内容。

提交内容即表示贡献者有权提供相关代码、文字和素材，并同意项目按 [MIT License](LICENSE) 使用这些内容。
