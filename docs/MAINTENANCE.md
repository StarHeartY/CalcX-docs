# 维护指南

CalcX-docs 当前由项目维护者主导，并使用 AI 辅助调查、编写和验证。维护采用事件驱动方式，不为了形式设置独立版本号、固定发布周期或复杂社区流程。

## 维护目标

- 用户手册与 CalculatorX 当前行为保持一致；
- 工程文档与仓库配置、目录和部署事实保持一致；
- `main` 始终能够由 Cloudflare Pages 自动构建；
- 生成产物可同时满足线上 `/docs` 和离线交付；
- 新加入的 AI 不依赖历史对话即可安全完成任务。

## 触发维护的事件

出现以下情况时执行对应检查：

| 事件 | 需要同步检查 |
| --- | --- |
| CalculatorX 功能或交互变化 | 对应 `pages/` 内容、截图、FAQ 和操作步骤 |
| 新增或移动页面 | `_meta.js`、站内链接、首页入口和锚点 |
| 依赖升级 | `package.json`、`package-lock.json`、Node 兼容性和完整构建 |
| 构建脚本变化 | `out/docs/`、图片转换、开发与部署文档 |
| Cloudflare 配置变化 | Pages 参数、Worker 路由、目标主机和部署指南 |
| CalculatorX 离线交付位置变化 | 只更新双方约定的交付路径，不复制客户端内部实现 |
| 收到失效链接或错误反馈 | 当前页面、相关页面和导航闭环 |

不要求固定周期发布。如果较长时间没有功能变化，可在重要 CalculatorX 发布前或依赖升级时顺带完成一次全站审计。

## 依赖维护

本项目统一使用 npm：

1. 在独立分支修改依赖；
2. 使用 `npm install` 更新 `package.json` 和 `package-lock.json`；
3. 阅读相关依赖的官方迁移说明；
4. 执行 `npm run build`；
5. 使用 Preview 部署检查首页、导航、搜索、公式和图片；
6. 合并后确认 Production 部署。

不要同时引入第二个包管理器或新的锁定文件。Node.js、Next.js、Nextra、React、TypeScript 和 Sharp 的升级都视为结构性变更。

Cloudflare 当前固定使用 Node.js 18。计划升级时先在本地和 Preview 环境验证，再调整生产环境变量，并同步更新 README、开发指南和部署指南。

## 内容维护

维护用户手册时：

- 从 CalculatorX 当前实现或维护者信息重新核实产品事实；
- 优先更新已有权威页面，不平行创建职责重复的新页面；
- 修改术语时搜索全站，保持按键、模块和设置名称一致；
- 更换截图时同时检查明暗主题、尺寸、隐私信息和 alt 文本；
- 修改标题或路径时检查所有内部链接和锚点；
- 占位页面完成后移除“敬请期待”等临时内容。

详细规则见[内容编写规范](CONTENT_GUIDE.md)。

## 工程文档维护

工程文档应描述当前状态，而不是历史讨论。发生以下变化时同步更新：

- 根目录或核心源码目录调整；
- npm 命令、Node 要求或构建输出改变；
- `/docs` basePath、`out/docs/` 或图片后处理改变；
- Cloudflare Pages、Worker 或生产分支改变；
- AI 的修改边界或验证规则改变。

新增文档前先查看[工程文档索引](README.md)，避免产生两个权威来源。专题文档新增后应加入索引，并从正文链接回索引或相关入口。

## 链接与导航审计

至少检查：

- README 和 `docs/` 中的相对文件链接；
- Markdown 标题锚点；
- `pages/` 与 `_meta.js` 的键是否对应；
- 首页卡片和正文链接是否存在真实目标；
- 外部官网、仓库、下载和支持链接；
- 明暗主题图片路径；
- Pages 原站与官网 `/docs` 的深层路由。

占位页面允许存在，但链接不得伪装成已经完成的教程。

## 生成目录与本地文件

- `.next/`、`out/`、`out_temp/` 和 `node_modules/` 不提交；
- 构建结果出现问题时修复源码，不直接编辑 `out/docs/`；
- PSD、日志和其他本地工作文件不得成为发布依赖；
- 删除文件前确认它不是源码或唯一素材，优先依靠 Git 保留可恢复历史。

## 发布前维护清单

- 当前修改范围清晰，没有无关格式化或清理；
- 产品事实和配置事实已核实；
- npm 锁定文件与依赖声明一致；
- 执行了与风险匹配的检查；
- 需要完整构建时，`out/docs/` 结构正确；
- 工程文档、本地链接和导航已同步；
- Preview 或 Production 地址未泄露私密信息；
- 交付说明写明已验证项和未验证项。

## AI 维护交接

AI 接手任务时应先读取 [`AGENTS.md`](../AGENTS.md) 和相关专题文档。完成后至少报告：

- 修改了哪些文件和用户可见行为；
- 事实来自哪些当前配置、源码或维护者信息；
- 执行了哪些验证；
- 哪些内容未验证以及原因；
- 是否需要维护者执行 Cloudflare 或 CalculatorX 外部操作。
